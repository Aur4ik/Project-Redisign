## 1. Тема Frontend MVP
**Тема проекта:** AlaAuto — веб-приложение автосалона для подбора автомобилей, сохранения понравившихся вариантов и демонстрационной записи на тест-драйв.

## 2. Целевой пользователь
Человек 20–45 лет, который планирует купить автомобиль для работы, семьи или ежедневных поездок. Обычно изучает варианты со смартфона или ноутбука, сравнивает стоимость и характеристики, хочет быстро найти машину в пределах бюджета и выбрать время знакомства с ней.

## 3. Основная задача приложения
Помочь пользователю подобрать подходящий автомобиль по марке, кузову и бюджету, изучить его характеристики и оставить учебную заявку на тест-драйв в одном интерфейсе.

## 4. Основные функции
1. Каталог автомобилей с поиском по марке и модели, фильтрами по марке, кузову и цене, сортировкой.
2. Просмотр подробной информации об автомобиле: стоимость, год, пробег, двигатель, коробка и привод.
3. Добавление автомобилей в избранное и удаление из него с сохранением после перезагрузки.
4. Создание демонстрационной заявки на тест-драйв с проверкой имени, телефона, даты и согласия на локальное хранение.
5. Просмотр и удаление собственных заявок, сохранённых в браузере.

## 5. Пользовательские сценарии
### Сценарий 1. Подбор автомобиля
**Пользователь и цель:** покупатель хочет найти кроссовер стоимостью до 20 млн тенге.

**Шаги:** открывает каталог → выбирает кузов «Кроссовер» → устанавливает бюджет «До 20 млн ₸» → просматривает результаты → открывает карточку Hyundai Tucson → изучает характеристики.

**Результат:** пользователь находит подходящий демонстрационный автомобиль и узнаёт его параметры и стоимость.

### Сценарий 2. Сохранение варианта
**Пользователь и цель:** покупатель хочет вернуться к понравившейся машине позже.

**Шаги:** открывает каталог → нажимает сердечко на Toyota Camry → переходит в «Избранное» → обновляет страницу → снова открывает «Избранное» и просматривает автомобиль.

**Результат:** автомобиль остаётся в сохранённой коллекции в этом браузере; его можно удалить повторным нажатием сердечка.

### Сценарий 3. Запись на тест-драйв
**Пользователь и цель:** покупатель хочет выбрать дату знакомства с автомобилем.

**Шаги:** открывает подробную карточку → нажимает «Записаться на тест-драйв» → вводит имя и телефон → выбирает дату и время → разрешает локальное хранение → отправляет форму → открывает «Мои заявки».

**Результат:** учебная заявка сохраняется в браузере и доступна для просмотра и удаления. Реальное бронирование в автосалоне не выполняется.

## 6. Основные страницы приложения
**Страница 1 — Каталог:** приветственный блок, автомобили, поиск, фильтры, сортировка и кнопки избранного.

**Страница 2 — Автомобиль:** иллюстрация, описание, стоимость и характеристики, переход к записи на тест-драйв.

**Страница 3 — Избранное:** сохранённые автомобили; их можно открыть или убрать из коллекции.

**Страница 4 — Тест-драйв / Мои заявки:** два связанных экрана: форма создания заявки с подтверждением и список сохранённых заявок с удалением.

Технически это SPA: переключение экранов выполняется состоянием React без перезагрузки страницы. Отдельных серверных URL у экранов в MVP нет.

## 7–9. Техническая настройка
Фактически выполненные шаги и ограничения указаны в файле STATUS.md рядом с этим листом. Неотмеченные шаги с GitHub необходимо завершить в своём аккаунте.

## Ограничения MVP
Данные автомобилей демонстрационные. Иллюстрации схематичные и не являются фотографиями конкретных моделей. Аккаунтов, реальной отправки заявок и серверной базы данных нет. Избранное и заявки хранятся в localStorage одного браузера и не синхронизируются между устройствами. Для проверки достаточно тестовых контактных данных.

## Связь с AlaRent
Использована идея каталога и выбора объекта: квартиры заменены автомобилями, характеристики жилья — характеристиками машины, целевой сценарий — заявкой на тест-драйв. Это новый фронтенд React/Vite, а не переименование серверного проекта Go. Сервер из AlaRent не подключён и в состав MVP не включён.
