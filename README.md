# AlaAuto — автосалон на React и Go

Полноценный учебный проект по подбору автомобилей и записи на тест-драйв. В основе — идея AlaRent, адаптированная под автосалон; архитектурный ориентир — exam_itStep: отдельный Go API, React-страницы, авторизация и роли.

## Быстрый запуск в Windows

Требуются Node.js 20.19+ (или 22.12+) и Go 1.25+. В терминале:

```powershell
cd C:\AlaAuto
npm install
npm start
```

Откройте **http://127.0.0.1:5173**. Первый запуск может занять время: Go скачивает зависимости и компилирует сервер. После сообщения `AlaAuto API: http://127.0.0.1:8081` регистрация и остальные функции доступны.

`npm start` запускает обе части. Остановка: Ctrl+C. Если один процесс завершился с ошибкой, второй останавливается. Порты 5173 и 8081 должны быть свободны; существующие проекты не останавливаются автоматически.

Раздельный запуск — в двух терминалах:

```powershell
# Терминал 1, C:\AlaAuto
npm run server

# Терминал 2, C:\AlaAuto
npm run dev
```

## Как пользоваться

1. Каталог доступен без входа. Можно искать машины, выбирать марку, кузов и бюджет, менять сортировку и открывать подробности.
2. Нажмите «Войти» → «Зарегистрироваться», создайте свой аккаунт.
3. Сохраняйте автомобили сердечком. Избранное привязано к аккаунту в серверной базе.
4. Откройте автомобиль → «Записаться на тест-драйв». Укажите имя, телефон, дату и свободное время; разрешите сохранение контактных данных.
5. В «Мои заявки» можно посмотреть статус и отменить активную заявку.

Это учебный автосалон: данные машин и цены демонстрационные; реальная компания заявки не получает. На начальных карточках — схематичные SVG-иллюстрации, а не фотографии моделей. Администратор может добавить HTTPS-ссылку на фотографию; при недоступности картинки показывается иллюстрация.

## Как открыть админку

Сначала зарегистрируйте обычный аккаунт через интерфейс. Затем в терминале в папке `C:\AlaAuto` выполните команду со своим email:

```powershell
npm run admin -- your-email@example.com
```

Команда работает локально с базой проекта и назначает роль только указанному существующему аккаунту. Это не публичный API. Вернитесь в интерфейс, обновите страницу или нажмите «Обновить профиль» — появится пункт **«Управление»**.

В админке доступны:
- список автомобилей, добавление и редактирование, изображение по ссылке;
- архивирование и восстановление машины через редактор;
- все заявки и их контакты, подтверждение и отмена;
- завершение подтверждённого тест-драйва после времени начала;
- список зарегистрированных пользователей.

Обычный пользователь не может получить админскую роль при регистрации или обратиться к административным маршрутам.

## База данных

По умолчанию используется SQLite: `backend/data/alaauto.db`. Таблицы и 6 начальных машин создаются автоматически. Пользователи, машины, избранное, заявки и сессии сохраняются между перезапусками. Подписывающий ключ автоматически создаётся в `backend/data/session.key`. Эти файлы не включаются в Git и архив исходников.

Для PostgreSQL вместо SQLite создайте отдельную базу и задайте в `backend/.env`:

```dotenv
DATABASE_URL=postgres://USER:PASSWORD@127.0.0.1:5432/alaauto?sslmode=disable
```

Не используйте базу AlaRent или exam_itStep. Для пароля со специальными символами нужна URL-кодировка. Подключение PostgreSQL реализовано, но в текущей среде проверен SQLite; PostgreSQL требует отдельного запуска и проверки на доступном сервере. Автоматического переноса данных SQLite в PostgreSQL нет.

Дополнительные настройки: `backend/.env.example`. Необязательно копировать его для локального запуска. Адрес API по умолчанию `127.0.0.1:8081`; при изменении адреса измените target в `vite.config.js`. За HTTPS используйте `COOKIE_SECURE=true` и собственный случайный `JWT_SECRET` длиной не менее 32 байт.

## Сборка и проверки

```powershell
npm run build
npm run test:server
```

После сборки можно запустить только `npm run server` и открыть **http://127.0.0.1:8081**: Go раздаёт собранный интерфейс из `dist`, включая прямые ссылки на внутренние страницы.

Проверки сервера используют изолированные временные базы, не меняют рабочие аккаунты и не требуют запущенного API. Они проверяют вход, роли, доступ к чужим заявкам, валидацию, архивирование, избранное, конкурирующие записи и сохранение данных после открытия базы заново. Подробности фактической проверки — в STATUS.md.

## Структура

```text
src/
  api/client.js             HTTP-клиент и форматирование
  context/                  авторизация, каталог и избранное
  components/               общие элементы и иллюстрация машины
  pages/                    каталог, вход, регистрация, карточка,
                            тест-драйв, заявки, профиль и админка
backend/
  cmd/server/main.go        запуск API и локальная команда администратора
  internal/app/
    config.go               соединение с БД и миграции
    models.go               модели базы
    auth.go                 регистрация, пароли, JWT-сессии, роли
    catalog.go              каталог и избранное
    bookings.go             заявки, свободное время и статусы
    routes.go               маршруты и HTTP middleware
    seed.go / seed.json     начальные автомобили
    app_test.go             интеграционные проверки API
scripts/                    совместный запуск и команды Go
WORKSHEET.md                заполненный рабочий лист
API.md                      описание API
STATUS.md                   проверки и ограничения
```

Файлы Go разделены по предметным областям внутри пакета app. Это компактный учебный модуль; отдельные repository/service-пакеты из референса намеренно не воспроизводятся для простых запросов без дополнительной логики.

## Технические решения

React, React Router, Vite, CSS; Go, Gin, GORM, SQLite/PostgreSQL. Пароли хешируются bcrypt, JWT хранится в HttpOnly cookie; сервер проверяет сессию и текущую роль в базе при каждом защищённом запросе. Выход отзывает сессию. Запись на занятое время защищена уникальным индексом базы. Отмена освобождает слот, завершённая заявка остаётся в истории. Время автосалона — UTC+5, запись доступна на будущие слоты в пределах 90 дней.

Vite проксирует /api на Go: и интерфейс, и cookie работают с одного origin. В браузерном localStorage больше не хранятся заявки или авторизация. Старые записи из Frontend MVP автоматически не импортируются: они не были связаны с аккаунтами.

## GitHub

Локальная история сохранена. Публикация на GitHub не выполнена. После создания пустого репозитория:

```powershell
git remote add origin https://github.com/YOUR_USERNAME/AlaAuto.git
git push -u origin main
```

В ZIP исходников нет .git: при работе из архива сначала выполните `git init -b main`, `git add .` и `git commit -m "Initial commit"`.

## Что ещё не входит в проект

Нет оплаты, кредитных расчётов, реальных интеграций автосалона, SMS/email-уведомлений, сброса пароля и загрузки фотографий файлами. Наличие этих функций не имитируется. Для публичного сервиса потребуются развёртывание за HTTPS, резервное копирование БД и дополнительные эксплуатационные настройки.
